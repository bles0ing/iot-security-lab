# RS485 双板指令扫描与应答验证

> **关键词**：STM32F103 · RS485 · UART 空闲中断 · 半双工通信 · 噪声免疫 · 嵌入式调试

## 项目简介

本项目实现了一个基于 RS485 总线的双板通信系统：
- **Scanner（扫描方）**：依次发送指令字节 `0x01` 到 `0x08`，逐个扫描，等待接收方针对每条指令回复 `ACK` 或 `NAK`，收到合法回复后在 OLED 上打印该指令码及应答结果。
- **Receiver（接收方）**：收到指令后判断其是否为**有效指令码**——`0x03` 和 `0x06` 视为有效，回复 `ACK`；其余（`0x01`、`0x02`、`0x04`、`0x05`、`0x07`、`0x08`）视为无效，回复 `NAK`，并在 OLED 上显示 `NORMAL` 或 `ABNORMAL`。同时通过 LED 指示判定结果：正常（有效指令）点亮 PA2 的灯，异常（无效指令）点亮 PA3 的灯。

旨在验证 RS485 半双工通信的可靠性，并解决上电/复位噪声导致的数据错位问题。

## 引脚映射

### UART3（RS485 收发，Scanner 与 Receiver 相同）

| 功能 | 引脚 | 说明 |
|------|------|------|
| DE（驱动使能） | PB9 | 高电平：发送使能 |
| RE（接收使能） | PB8 | 低电平：接收使能（MAX485 通常 RE 与 DE 逻辑相反，具体以模块为准） |
| DI（数据输入） | PB10 | 接 USART3_TX |
| RO（数据输出） | PB11 | 接 USART3_RX |

> USART3 的 TX/RX 复用映射到 PB10/PB11。DE 与 RE 分开由 GPIO 控制，发送前拉高 DE、拉低 RE；接收前拉低 DE、拉高 RE。

### 其他引脚

| 功能 | 引脚 | 说明 |
|------|------|------|
| LED 正常（G_LED） | PA2 | 收到有效指令（ACK）时点亮 |
| LED 异常（B_LED） | PA3 | 收到无效指令（NAK）时点亮 |
| 调试串口（USART1） | PA9（TX）、PA10（RX） | 通过 USB 转串口模块连接电脑，用于 `printf` 打印调试信息 |
| OLED（I2C） | PB6（SCL）、PB7（SDA） | 显示扫描状态与结果（以实际配置为准） |

## 接线图

### 两块 STM32 板之间的 RS485 总线

```
Scanner (板A)                Receiver (板B)
  PB10 (DI/TX) ─────────── PA10 (RO/RX)
  PB11 (RO/RX) ─────────── PA9 (DI/TX)
  PB9  (DE)                 PB9  (DE)
  PB8  (RE)                 PB8  (RE)
  A (+) ─────────────────── A (+)
  B (-) ─────────────────── B (-)
  GND ───────────────────── GND
```

> DE/RE 由各自 MCU 独立控制。RS485 模块的 A/B 线交叉连接（A 接 A，B 接 B）。**注意**：DI/RO 与对端 RO/DI 交叉（TX 接 RX），与 UART 直连一致。

### Scanner 与电脑（调试串口）

```
Scanner PA9 (USART1_TX) ── USB转串口模块 RXD
Scanner PA10(USART1_RX) ── USB转串口模块 TXD
GND                       ── GND
```

## 指令集与应答规则

Scanner 依次发送以下 8 个指令字节：

| 指令码 | 含义 | Receiver 判定 | 回复 | LED |
|--------|------|---------------|------|-----|
| `0x01` | 指令 1 | 无效 | `NAK` | PA3 亮（异常） |
| `0x02` | 指令 2 | 无效 | `NAK` | PA3 亮（异常） |
| `0x03` | 指令 3 | **有效** | `ACK` | PA2 亮（正常） |
| `0x04` | 指令 4 | 无效 | `NAK` | PA3 亮（异常） |
| `0x05` | 指令 5 | 无效 | `NAK` | PA3 亮（异常） |
| `0x06` | 指令 6 | **有效** | `ACK` | PA2 亮（正常） |
| `0x07` | 指令 7 | 无效 | `NAK` | PA3 亮（异常） |
| `0x08` | 指令 8 | 无效 | `NAK` | PA3 亮（异常） |

**有效指令码**：`0x03`、`0x06`
**应答**：`ACK`（ASCII，0x41 0x43 0x4B）或 `NAK`（0x4E 0x41 0x4B）

## 通信协议

```
Scanner                         Receiver
  |                                |
  |---- [0x01 ~ 0x08] ----------->|
  |                                |-- 判断是否为 0x03/0x06
  |<--- "ACK" (有效) / "NAK" (无效)|
  |                                |-- 点亮 PA2/PA3 LED
  |-- 收到应答 → 打印指令码及结果  |
```

扫描流程：Scanner 从 `0x01` 开始，每按一次按键发送一个指令码，直到 `0x08`；Receiver 对每条指令即时判定并回复，同时点亮对应的 LED（PA2 正常 / PA3 异常）；Scanner 收到回复后通过 OLED 与调试串口（USART1）打印该指令码及 `ACK`/`NAK`，用于验证通信与指令有效性。

## 调试记录（踩坑过程）

### 坑1：OLED 在中断中刷新，画面卡死
- **现象**：OLED 只刷新一次，之后无反应。
- **原因**：在 `HAL_UARTEx_RxEventCallback` 中直接调用 OLED 刷屏函数，阻塞了中断。
- **解决**：回调中只置标志位，所有耗时操作移到主循环处理。

### 坑2：指令码与应答永远错一位
- **现象**：发送 `0x03` 后，收到 ACK 却打印下一条 `0x04` 的信息；发送 `0x06` 却打印 `0x07`。
- **原因**：使用了两个独立计数器 `count`（发送时递增）和 `cnt`（接收时递增），异步操作导致索引失步，打印的总是"下一个未发送的字节"。
- **解决**：统一使用 `count`，接收处理中打印 `arr[count-1]`（即刚发送的那条指令），不再维护单独的 `cnt`。

### 坑3：板子硬件问题导致通信不稳定
- **现象**：互换两块板子的角色后，其中一块始终无法正常接收（连之前的 CAN 回环测试也不通过）。
- **原因**：该板子的 UART 接收通路存在硬件缺陷（可能是虚焊或芯片在 CAN 实验时受损）。
- **解决**：将该板固定作为 Scanner（发送方，其 TX 正常），另一块作为 Receiver（接收方），并计划更换新板。

### 坑4：复位接收端导致发送端误触发接收（关键转折）
- **现象**：按下 Receiver 的复位键，Scanner 的 OLED 突然显示 `01` 及其应答信息，但此时并没有按按键。
- **原因**：复位瞬间 RS485 总线产生电平噪声，被 Scanner 的 UART 误判为一帧有效数据，触发了空闲中断，执行了接收处理代码，导致 `count` 状态被错误推进。
- **解决**：在接收处理中增加 `memcmp` 过滤，只处理前 3 字节为 `"ACK"` 或 `"NAK"` 的数据，其余（噪声、残帧）全部丢弃，不改变任何计数状态。同时在硬件上加偏置电阻（A 上拉、B 下拉）抑制噪声。

## 运行效果

- **有效指令**：Scanner 发送 `0x03` → Receiver 判定有效 → 点亮 PA2 LED → 回复 `ACK` → Scanner OLED 显示 `03 ACK`；发送 `0x06` 同理显示 `06 ACK`。
- **无效指令**：Scanner 发送 `0x01`/`0x02`/`0x04`/`0x05`/`0x07`/`0x08` → Receiver 判定无效 → 点亮 PA3 LED → 回复 `NAK` → Scanner 显示如 `01 NAK`。
- **扫描流程**：从 `0x01` 扫描到 `0x08`，每条指令对应一次按键，Scanner 通过调试串口（USART1）打印有效指令码，便于核对。扫描结束后 OLED 不显示 `DONE`（本项目未实现扫描完成提示，如需可自行扩展）。
- **噪声免疫**：复位任意一块板子，另一块板子不会误触发接收处理，计数状态不受影响，下次按键仍从正确指令继续。

## 结论与延伸

### 调试方法论总结
1. **中断中只做最轻量的事**（置标志），主循环处理业务逻辑。
2. **索引变量统一管理**，避免多个计数器异步失步。
3. **数据合法性过滤**（`memcmp` 校验 `ACK`/`NAK`）是防御上电/复位噪声的最简单有效手段。
4. **硬件偏置电阻** 能从物理层减少噪声触发概率，与软件过滤互补。
