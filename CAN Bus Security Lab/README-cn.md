# CAN 总线安全攻防实验

## 一、 硬件配置

| 组件 | 规格/数量 | 备注 |
| :--- | :--- | :--- |
| **主控芯片** | 2x STM32F103C8T6 | 攻击节点 + 接收节点 |
| **CAN 收发器** | 2x TJA1050 模块 | **内置 120Ω 终端电阻** |
| **状态指示** | 1x 蓝灯 + 2x 红灯 | 蓝灯(正常) / 红灯(报警) |
| **显示设备** | 0.96寸 OLED (I2C) | 显示原始 HEX 数据 |
| **报警装置** | 无 | 未使用蜂鸣器 |

## 二、 报文数据定义 (Payload)

实验中使用预定义的数组作为 CAN 报文的数据域 (Data[8])：

c
// 低速报文 (示例: 10 km/h)
uint8_t speed_l[8]={0x00,0x00,0x00,0x00,0x00,0x00,0x00,0x0A};

// 高速报文 (示例: 1000 km/h - 用于异常测试)
uint8_t speed_h[8]={0x00,0x00,0x00,0x00,0x00,0x00,0x03,0xE8};

// 垃圾报文 (全 0xFF - 用于洪泛/干扰测试)
uint8_t rubbish[8]={0xFF,0xFF,0xFF,0xFF,0xFF,0xFF,0xFF,0xFF};


## 三、 实验现象与状态

### 1. 正常通信 (Normal)
*   **触发条件**：节点发送 `speed_l` 等合法数据。
*   **LED 状态**：**蓝灯常亮**。
*   **OLED 显示**：接收到的 8 字节原始十六进制数据。

### 2. 节点伪造攻击 (Spoofing)
*   **触发条件**：节点发送 `speed_h`（超出行车物理极限的数据）。
*   **LED 状态**：**两个红灯亮起**。
*   **OLED 显示**：接收到的高位速度数据 (`...0x03, 0xE8`)。

### 3. DoS 洪泛攻击 (Flooding)
*   **触发条件**：高频发送 `rubbish` 数据，**频率 > 60 帧/秒**。
*   **LED 状态**：**两个红灯快速闪烁**。
*   **OLED 显示**：屏幕卡顿或显示 "FLOOD" 报警字样。

## 四、 防御系统说明 (IDS)

本系统采用轻量级白名单规则进行检测：

1.  **数据范围检测**：解析 Data[7] 和 Data[6]，若计算出的速度值超过预设安全阈值（如 120 km/h），判定为 **Spoofing**。
2.  **频率检测**：统计同一 ID 报文的到达频率，若 **> 60 FPS**，判定为 **Flooding**。

## 五、 关于重放攻击 (Replay Attack)

*   **代码状态**：在 `/test/` 目录下保留了重放攻击测试代码，但在主程序中已 **注释**。
*   **原因**：由于重放攻击发送的是历史合法报文（符合白名单规则且频率正常），当前的 IDS 无法识别此类“伪装正常”的流量。为避免演示歧义，正式实验中禁用该模式。
