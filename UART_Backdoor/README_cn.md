# UART 后门植入实验（进阶版）

## 实验目的
在 STM32（HAL 库）上实现一个具备隐蔽性的 UART 后门，理解固件级后门的触发机制、命令控制与防御逃逸思路，作为工控/IoT 固件安全方向的入门实践。

## 触发机制（双重验证）
- 物理触发：按下板载按键 `KEY1`
- 口令触发：串口（USART1）发送口令 `backroot` 并回车
- 两者同时满足才进入后门模式，避免误触或被单纯爆破口令触发
- 采用状态机（`bk_status`）切换正常/后门模式，后门处理不阻塞主循环

## 命令集
进入后门模式后，串口响应以下命令（正常模式下串口静默）：

| 命令 | 作用 |
|---|---|
| `help` | 查看命令列表 |
| `led on` | 点亮绿灯（`G_LED_ON_ONLY`） |
| `unlock` | 退出后门模式，恢复 OLED 显示 `System OK` |

## 锁定与隐蔽设计
- 口令错误累计 3 次，OLED 显示 `System Lock`，锁定 10 秒后自动解锁
- 后门激活期间 OLED 仍显示 `System OK`（伪装），红灯快闪作为隐蔽提示
- 退出后门后状态清零，系统恢复如常

## 遇到的问题与解决
实现过程中遇到的三个典型问题，直接推动了架构从"功能可用"演进为"状态机驱动"：

1. **串口争夺（UART 资源竞争）**：后门处理与主循环共用 USART1，激活期间打印与命令接收互相抢占，出现输出混乱、命令截断。解决：明确"生产者—消费者"边界——空闲中断只负责填充 `RxBuf`，`printf`/OLED 走独立通道，命令由主循环统一消费。
2. **缓冲区未接收完全而引入延时**：初版为"等一帧收完"加入 `HAL_Delay` 等待缓冲区填满或等待结束符到位，既拖慢响应，又阻塞了主循环的周期任务。解决：改用 `HAL_UARTEx_ReceiveToIdle_IT` 空闲中断接收，总线空闲即触发回调、数据到达即消费，彻底去掉阻塞式延时。
3. **进入功能模式后卡住主循环**：初版在后门激活后使用 `while(1)` 死循环等待命令，CPU 被独占，LED 闪烁、OLED 刷新、喂狗全部停滞，系统形同"死机"。解决：引入 `bk_status` 状态机并由主循环统一调度，每次只处理一条命令即返回，后门任务不再独占 CPU。

> 三个问题的解决落到一个统一的设计原则上：**中断只填缓冲、空闲中断去除延时、状态机保障主循环畅通**——这也是本实验从"能跑"到"架构合理"的关键。

## 功能验证（已硬件验证通过）
- 平台：STM32F103C8T6 + CH340（USB-TTL）
- 接线：CH340 TX→PA10(RX)、RX→PA9(TX)、GND→GND；KEY1 接 PC13
- 验证项：正常模式静默、双重触发进入后门、help/led on/unlock 命令、3 次错误锁定、10 秒自动解锁——均通过

## 安全分析
- 攻击链视角：物理接触 + 口令 → 触发后门 → 信息查询/IO 控制 → 撤离（unlock 恢复伪装）
- 局限性：口令硬编码于固件，可被 dump 提取；后续可扩展 `dump`/`write`/`gpio` 命令、加入 CRC 自检与多因子认证

## 结论
完成了从"51 单片机指令控制"到"STM32 状态机后门"的进阶，掌握了 UART 空闲中断接收、GPIO/按键中断、OLED 显示与固件安全的基本认知。更重要的是，通过解决串口争夺、缓冲区延时、主循环阻塞三个实际问题，形成了"中断填缓冲 + 状态机调度"的嵌入式后门实现范式，为后续固件逆向（Ghidra/IDA）与无线安全学习打下基础。
