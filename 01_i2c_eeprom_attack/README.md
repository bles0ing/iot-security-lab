# I2C EEPROM 物理篡改攻击实验

## 实验目的

验证工控设备外部 EEPROM 配置可被物理篡改且无校验机制的安全风险。通过 CH341A 编程器直接读写 AT24C02 芯片，篡改存储内容，使设备上线后信任被污染的数据并改变行为。

## 硬件环境

| 器件 | 型号 | 作用 |
|---|---|---|
| MCU | STM32F103C8T6（蓝药丸） | 主控，I2C 主设备 |
| EEPROM | AT24C02（DIP8） | 外部配置存储 |
| 显示器 | 0.96" OLED（I2C） | 显示 EEPROM 内容 |
| 编程器 | CH341A Mini Programmer | 物理读写 EEPROM |
| 分析仪 | 逻辑分析仪（24MHz） | 嗅探 I2C 总线 |

## 实验步骤

### 1. 正常通信验证

STM32 上电后检测 AT24C02 是否为空芯片（首字节 0xFF）。若为空，写入默认值 `"SECURE_2026"`，OLED 显示该字符串。

### 2. 逻辑分析仪嗅探

连接逻辑分析仪探头至 SCL（PB6）和 SDA（PB7），PulseView 解码 I2C 协议，确认数据以明文传输，无加密无校验。

### 3. CH341A 物理篡改

断电后拔出 AT24C02，插入 CH341A 编程器 ZIF 座（1 脚朝向手柄侧，电压跳线 3.3V），使用 NeoProgrammer 读取内容为 `"SECURE_2026"`，将 `"SECURE"` 改为 `"HACKED"`，保存为 `hacked.bin` 并写回芯片。

### 4. 篡改后验证

将 AT24C02 插回 STM32 系统，上电后 OLED 显示 `"HACKED_2026"`。按复位键多次，内容保持不变，攻击持久化成功。

## 遇到的问题与解决

| 问题 | 原因 | 解决方案 |
|---|---|---|
| CH341A 驱动未识别 | 驱动未正确安装 | 重装 CH341 驱动，换 USB 口 |
| 找不到 SDA/SCL 丝印 | 购买的为 CH341B 版本，排针布局不同 | 对照 datasheet + 万用表测量定位 |
| 跳帽遮挡无法夹芯片 | AT24C02 模块跳帽挡住 SOIC8 测试夹 | 拔掉跳帽，从排针下孔引出杜邦线 |
| 复位后篡改内容被覆盖 | 原代码每次上电都重写 EEPROM | 改为"上电只读，空芯片才写默认值" |
| 芯片插入方向不确定 | ZIF 座 24xx 区域标记不直观 | 以丝印半圆标记为准，缺口朝手柄侧 |

## 安全分析

### 攻击面

- 外部 EEPROM 物理可接触，无需授权即可拔出
- I2C 总线明文传输，逻辑分析仪可直接嗅探
- 设备无条件信任 EEPROM 中的配置数据

### 攻击持久化

- 篡改后的数据写入非易失性存储器
- 设备代码逻辑为"只读不写"，不会覆盖被篡改内容
- 断电/复位均不影响篡改状态

### 防御建议

- EEPROM 中存储校验和或数字签名，上电时验证完整性
- 关键配置加密存储，MCU 端解密后使用
- 检测异常配置内容（如非预期字符串），触发告警
- 将关键配置移至 MCU 内部 Flash 或 OTP 区域

## 实验结论

成功复现了 I2C EEPROM 物理篡改攻击的完整链路：嗅探 → 提取 → 篡改 → 持久化。证明当外部存储中的配置可被物理访问且设备无校验机制时，攻击者可以持久地控制设备行为。
